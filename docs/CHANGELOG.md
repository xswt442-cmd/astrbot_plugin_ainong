## [未发布]

### 新增

- **`/爱农 <没匹配上子命令的内容>` 自己接住。** 以前这类消息被 AstrBot 跳过
  指令、原样进模型，模型收到一句普通提问就自己编。现在回一句该发什么。
  组名另外补上带斜杠的别名：QQ 官方的 At 唤醒分支不剥 `message_str` 里的 `/`，
  `@机器人 /爱农 战绩` 的组名匹配不上，整条指令静默失败。

### 变更

- **「开一局」的输出第一行写明这是推演**，与爱瓦、爱完美同一句。用户看到一串
  K/D/A 分不出真假，那一行是唯一的提示。
- 提示词补上「只说数据支撑得住的话」：列表接口没有经济与伤害，模型以前会照着
  别的游戏的指标体系编。PK 的分数也改成与两人的实际差距相符，不再笼统要求
  「敢于给大的分差」，并钉住胜者那一行必须与分数一致。
- 用户可见文案统一：模型出错一律说「调用模型失败」，未绑定一律先说怎么绑定。

### 修正

- `__init__` 的 `config` 改成可省。AstrBot 读不到配置项时不会传它，声明成必需
  参数会让插件整个加载不起来——爱瓦、爱完美都踩过这一条。

## [0.1.12] - 2026-10-12

### 变更

- `/爱农 PK` 的「互损」改成**主要攻击输的一方**最难看的那一项（带具体数字或
  英雄名），赢的一方顺带攻击一下就行。原来要求双方各点一项缺点——两边都重点
  攻击等于没有倾向，反而像端水。

## [0.1.11] - 2026-10-12

### 新增

- **`/爱农 开一局`** —— 假设他又开了一局排位，让模型推演过程与结果，输出固定六段
  （选人／开局／中期／决胜／结算／赛后）。**胜负由 `stats.抽对局结果` 按他自己的

  「超神带飞」，而一个 45% 胜率的号不该这样。概率收到 0.1~0.9，满胜率也照样会输。

- AGENTS.md 里两个 PK 小节合成一个（164 → 153 行）。

## [0.1.10] - 2026-10-12

### 新增

- **`/爱农 PK <昵称>`** —— 和另一个人比近期战绩。双方各绑自己的营地账号，
  模型给两人一个 0-100 的趣味综合分、判定胜者并点出胜负手。

  对手的定位顺序：先看消息里的 `@` 组件与正文里的 `<@!id>`，没绑定过就按
  **群昵称**找。昵称是 QQ 官方平台上的主路径 —— 实测群里 @ 别人时，事件里
  拿到的组件是 `['qq_official', None]`、正文是 `'爱农 PK'`，被 @ 的人的标识
  完全不出现（适配器只把「@机器人」转成组件；引用消息也只给消息 ID，不给作者）。
  机器人自己的绑定会被排除；名字撞车时列出来让人写完整一点。

  **逐项对比由代码算死再交给模型解说**，不是丢两份数据让它自己比。第一版就是
  后者，实测出来 83 对 87，完全看不出输赢、点评也是端水话。现在 `stats.对比要点`
  把七项（胜率／KDA／评分／MVP／场均击杀／场均死亡／近 10 场胜场）逐项比出高低，
  提示里写死「不许重算、不许推翻对比结论」「分数按实际情况给差距、敢于给大
  分差」，并把端水词列成禁令（各有千秋、不相上下、势均力敌…）。占优项数只作
  参考——**占优项多的一方不一定更强**，哪几项占优才决定输赢，判断留给模型。
  「互损」要点名双方各自最难看的那一项，对输的一方更狠一点。

  **逐项对比由代码算死再交给模型解说**，不是丢两份数据让它自己比。第一版就是
  后者，实测出来 83 对 87，完全看不出输赢、点评也是端水话。现在 `stats.对比要点`

- **`/爱农 昵称 <名字>`** —— 给自己起一个 PK 用的名字。绑定时会自动取平台显示名
  当默认值，但 QQ 官方平台给的是 **QQ 昵称而不是群昵称**（实测有人是「……」），
  照那个名字根本点不到人，所以留了自助的出口。绑定成功的提示里会报出当前名字。
- **`/爱农 昵称 <名字>`** —— 给自己起一个 PK 用的名字。绑定时会自动取平台显示名
  当默认值，但 QQ 官方平台给的是 **QQ 昵称而不是群昵称**（实测有人是「……」），
  照那个名字根本点不到人，所以留了自助的出口。绑定成功的提示里会报出当前名字。
- **`/爱农 锐评` 有了固定版式**：先给一句称号（形如「你最近是个星耀局靠牛魔
  吃红利的团队工具人」，称号里要带段位或招牌英雄），再分「打得好／问题／建议」
  三段。同时要求正文至少出现 3 个具体数字，并禁掉端水词。
- **战绩维度补全**（字段语义逐条用真实响应核实过，见 AGENTS.md）：星数、巅峰分

  胜负走势、最长连胜；模式分布超过三项时合并成「其他 N 场」。
  接口没返回的维度直接不显示——0 是合法数据，「没有这项」不是，不能用 0 充数。
- 绑定时会顺手记下平台显示名，PK 时能念出双方名字。

### 修复

两处都在 QQ 绑定那条路上，表现都是「扫完了却绑不上」。

- **一次绑定会连着收到两张二维码，而且第一张必然失效。** 出码之后，后台等待
  协程一进循环就无条件换页 + 取图 + 推送，可 `出码()` 刚刚才给过用户一张；
  更麻烦的是那次换页会重新加载授权页，让第一张当场作废。现在改成先让第一张
  用满自己的刷新间隔再去换，每次换码只推一张。
- **扫码成功后抛 AttributeError，绑定中断。** 回调那行写的是
  `lambda code: self._完成(换取平台凭据(code))`，而 `_完成` 是 `_绑定` 里的
  **局部函数**，`self._完成` 根本不存在——线上日志就是
  `'Main' object has no attribute '_完成'`。同一行还有第二处：`换取平台凭据`
  是协程函数，没有 await，实际传下去的是一个**从未被 await 的协程对象**
  而不是凭据字典。现在收成一个协程，先 await 换票再落地。

两处都补了回归测试，并且都在退回旧代码后确认会红。

## [0.1.6] - 2026-10-12

### 修复

- **扫码成功但绑定没反应。** 回调签名对不上：`_收到授权码(用户, 授权码)` 要两个
  参数，而 `等授权码` 拿到授权码后只传一个。调用即 TypeError，异常发生在没人
  看的后台 task 里，用户看到微信提示"扫码已登上"却什么都没发生。现在用闭包把
  用户标识绑掉，回调只收授权码
- **扫码失败后会话不清。** 超时或二维码失效时异常从 task 抛走，会话条目留在
  字典里，用户再发绑定只会一直看到"扫码已经在进行中"，而他其实什么都没在扫。
  现在所有失败都交给出错回调，清场并告知用户
- **关闭会话时不等 task 收尾。** 取消是异步的，立刻关 http 会话会让正在轮询的
  那一下抛连接错误

### 新增

- `/爱农 状态`（别名 `status`）。报自己的标识、绑定情况、有没有卡住的扫码会话，
  主动查进度用
- 扫码结果优先走被动回复。QQ 官方 bot 在群里的主动消息要群授权、每条还消耗
  额度（实测报「主动消息失败, 无权限」40034105），而带 msg_id 的被动回复不
  需要。原来的实现只用主动消息，日志里成功通知的次数是 0

### 变更

- 扫码会话挪进 `ainong/auth/scan_session.py`。原先在 main.py 里，本地没有
  astrbot 包就没法测它，逻辑只能靠人工点。现在有 14 项测试覆盖

## [0.1.4] - 2026-10-12

### 修复

- `/爱农 绑定` 发不出二维码。原先用 `event.chain_result([Image, "文本"])` 拼

### 修复

- `release` 工作流里的 shell 变量名改为 ASCII。GitHub runner 的 bash 不接受
  非 ASCII 标识符，`版本=v0.1.4` 直接 `command not found`，`$版本` 静默展开成
  空，于是版本号检查恒失败。约束由 `test/test_workflow_shell.py` 检查

## [0.1.3] - 2026-10-12

### 修复

- `requirements.txt` 不再由 `uv export` 生成。该工具会把每个包钉成 `==`，
  而 AstrBot 核心自带 aiohttp、cryptography 并有版本护栏：插件要求
  `aiohttp==3.14.5` 而核心装的是 3.14.3，pip 需要动核心的包，护栏拦下，
  从插件市场安装直接失败。改为手写范围约束，pip 认为已装版本已满足、不动手

## [0.1.0] - 2026-10-11

首个版本。

### 新增

- 插件图标。放在根目录的 `logo.png`，WebUI 的插件列表会显示它
- 绑定自己的王者营地账号：一个 Bot 用户对应一个营地账号，账号下的多个
  游戏角色可切换
- `/爱农 战绩` 输出近期战绩摘要，`/爱农 锐评` 让模型基于这些数据写评价
- 模型可调用的 Tool，问话时自动读取提问者的战绩
- 营地协议层：XXTEA 加解密、PKCS#1 v1.5 块解析、YSDK 请求签名、
  分块 RSA、营地登录与设备指纹
- 微信扫码登录，全流程 HTTP，不依赖浏览器
- 按账号维度的频控：最小请求间隔与命中频控后的冷却
- 浏览器服务的 compose 片段与 seccomp 配置，供 QQ 扫码使用

### 已知限制

- QQ 扫码需要额外部署浏览器服务，见`deploy/`
- 营地接口对账号限流，命中频控后冷却 12 小时，期间该账号的查询会被拒绝
